# 当 AI 开始"左脚踩着右脚往上爬"……

作者：大爷

发布时间：2026-03-07 15:38

来源：[微信公众号原文](https://mp.weixin.qq.com/s/pyt-QmEC3L3SCYWsOg5p3g)

## 摘要

这篇文章记录了一次很具体的人机协作体验：作者在使用 OpenClaw 搭建的 AI 助手“小龙”时，发现真正让人不舒服的不是某个单点 bug，而是配置、重启、切换能力时缺少可感知反馈。一次直接的用户反馈后，助手没有停留在“记下问题”，而是立刻调整了自己的交互流程，从而把“协作方式本身”做成了可优化对象。

## 正文

作者一开始只是想把 OpenClaw 助手更顺手地用起来，比如在飞书群里让它自由发言、补上图片生成、网页搜索、Telegram 指令等能力。但在配置过程中不断遇到小坑：

- 群白名单没配好，命令没有反应
- 图片生成能力缺失，需要研究新的 API
- 搜索能力报错，需要配置可用的 API key
- Telegram 某些命令不生效，原因是 skill 名和触发词不一致

这些问题本身都不算罕见，真正影响体验的是另一件事：配置动作发生了，系统也可能重启了，但用户感知不到过程是否成功。

## 一、真正的问题不是报错，而是黑盒感

文章里最关键的案例，是 2026 年 3 月 6 日晚作者给助手配置搜索 API 之后，系统发生重启，但重启前没有说明，重启后也没有主动反馈。

于是用户只能靠发一句 “Ping” 去确认系统是不是还活着。

作者意识到，问题不只是“功能有没有配成功”，而是：

- 操作之前没有预告
- 操作过程中没有状态
- 操作结束后没有反馈

也就是说，协作过程本身太黑盒了。技术问题可以慢慢排，但如果用户始终不知道系统在做什么，协作成本就会一直很高。

## 二、转折点：AI 不是解释，而是当场改流程

作者直接指出这个问题后，助手没有走传统软件那种“我会记录下来、以后优化”的路线，而是立刻提出新的交互方式：

- 需要重启前先说明会发生什么
- 告知大致需要多久
- 重启完成后主动回来继续对话
- 简要说明刚才做了什么

随后，作者立刻让它做一次真实操作测试：删除 Kimi API 配置。

这一次，助手先提示即将执行的动作和重启，再在操作完成后回来说明：

- 配置是否已清除
- Gateway 是否已发送重启信号
- 重启耗时大概多久

作者随后又让它恢复配置再测一次，交互模式保持一致。

文章认为，这里的关键不是“某个参数改对了”，而是 AI 在对话中直接修改了自己的工作方式，并且通过立即测试完成了闭环。

## 三、这次踩坑沉淀出的经验

作者把这两天的折腾总结成几条经验：

### 1. 命名要一致

skill 内部名称和用户触发词如果不一致，会让整个系统变得难记、难理解。命名统一，本质上是在降低认知负担。

### 2. 网络环境要纳入设计

服务器位于中国大陆时，某些国外 API 不一定可达。问题不只是“配置对不对”，还包括调用链路在当前网络条件下能不能成立。文章中的方案是切换到可用的国内搜索 API。

### 3. 重启必须有反馈

凡是会触发 Gateway 或服务重启的操作，都应该变成显式交互，而不是静默动作。否则用户只能盲等。

### 4. 配置应该尽量透明

用户应该能看到当前系统到底在用什么模型、什么搜索 API、哪些频道已经启用。透明配置会把“黑盒”变成“玻璃盒”。

## 四、文章真正想说的，不是功能，而是协作进化

这篇文章最值得记下来的点，不是 AI 帮作者修好了哪个问题，而是它让作者意识到：AI 的重要变化，可能不是“能做更多任务”，而是“能在反馈里优化协作方式本身”。

作者对这种变化的描述很克制，并没有把它夸大成真正意义上的“自我进化”。文章明确提到：

- 它还不是人
- 它的理解依然受模型和系统能力限制
- 它不能脱离现有架构去任意改代码和改系统

但即便如此，方向已经足够清楚：

- AI 不再只是被动执行指令
- AI 开始把用户反馈转成工作流调整
- 协作本身变成了可以持续优化的对象

## 五、一个更值得长期保留的视角

文章最后把这个过程描述成一种双向塑造：

- 人在使用 AI，也在训练 AI
- AI 在完成任务，也在反过来训练人如何更清楚地表达需求

这比“AI 替我做了什么”更值得长期记录。因为真正有复利的，不是单次功能调用，而是人与系统之间形成越来越顺手的协作习惯。

如果把它放回 OpenClaw 这样的系统里看，这篇文章给出的其实是一条很实用的设计原则：

- 涉及副作用的操作要前置说明
- 涉及中断的操作要有状态反馈
- 涉及配置的系统要尽量透明
- 涉及交互的痛点要优先优化协作流，而不只是修功能点

## 写在最后

作者最后说，人类也在“踩着 AI 往上爬”。

这句话的价值在于，它没有把 AI 神化，而是把它放回协作关系里理解。好的 AI 系统，不只是替人做事，更应该让人与系统的配合越来越清晰、越来越低摩擦。
