## 原文正文（文本提取）

一次它在对话中当场改进自己的真实记录
锤子不会因为你说"砸得不够准"而自己调整重心。但 AI 助手不一样——它会根据你的反馈调整行为，会记住你的偏好，会主动发现问题。

昨天，我的 AI 助手做了一件让我愣住的事。
它不是帮我完成了某个任务，也不是给了我什么答案——而是在和我的对话里，它当场改掉了自己不好的工作方式。
不是"我会把这个问题反馈给开发团队"，也不是"这个问题会在未来版本中优化"。就是当时，立刻，改了。

这件事让我意识到，AI 最值得注意的变化，可能不是它变得越来越聪明、能做越来越多的事，而是它开始能在协作中改进协作本身。
这篇文章不是在讲"AI 帮我做了什么"，而是在讲"AI 和我一起，把怎么合作这件事越磨越顺"。

一、起点：一个笨拙的助手
事情要从两天前说起。
我在飞书群里和 AI 助手聊天——它叫"小龙"，是我用 OpenClaw 搭的一个助手。群里还有其他朋友，我希望小龙能自由发言，不需要每次都 @它。
于是我发了/allow-group命令。
没反应。
小龙告诉我：这个群不在白名单里。于是我们花了点时间，把几个常用的群加入了配置列表。
这只是开始。
接下来两天，我们遇到了一堆类似的情况：图片生成能力没有，需要研究 GLM-Image API；网页搜索报错，需要配置 API key；Telegram 群里某个命令不执行，发现是 skill 名和触发词对不上……
每一个问题，都是一次"你问我答"的来回。我在发现问题，它在解决问题。
这些折腾本身没什么特别，配环境嘛，总会遇到各种小坑。但有一个体验，让我开始觉得不太对劲。

二、真正的问题：配置后的沉默
3月6日晚上，我给小龙提供了搜索的 API key。
它配置完成后，整个系统重启了。
然后……就没有然后了。
我不知道重启成功了没有，不知道搜索能不能用了，甚至不知道它是不是"死"了。我只能试探性地发了句："Ping"。
它回了"Pong"。
好吧，至少还活着。
但这个体验让我很困惑。配置个东西，怎么像在黑盒子里操作？
系统动了，但我不确定它动了。操作完成了，但我不知道成没完成。
回过头看，这两天踩的所有坑，真正让我不舒服的，不是哪个功能有 bug，而是这种"事情发生了，但我感知不到"的黑盒感。技术细节可以慢慢调，但协作过程本身太不透明，人就会很累。
于是我对它说：
"你每次重新启动 Gateway 的时候，没有消息反馈，会导致我以为出问题了。而且你配置的内容，在重新启动后并没有继续回答，交互性太差。可以怎么优化一下吗？"

它的回答，让我意外。

三、转折：它当场改了
小龙没有解释为什么会这样，也没有说"这个问题我记下了"。它说：
以后涉及 Gateway 重启的操作，我会：

- 提前告诉你"需要重启，大约多久"

- 重启后主动说"重启完成，我们继续"

- 简要说明刚才做了什么

要测试一下吗？

我说："好，你删除一下 Kimi 的 API。"
于是它开始了改进后的第一次操作——

---
小龙：
准备操作：

- 清除 Kimi Search API 配置

- ⚠️ Gateway 将重启（约 5-10 秒）

- 重启后我会通知你结果

执行中...

---
几秒后：

---
小龙：
✅ 操作完成！
发生了什么：

- ✅ Kimi Search API 配置已清除

- ✅ Gateway 重启信号已发送

- ✅ 重启延迟：2 秒

这就是改进后的体验：

- ✅ 提前告知操作内容

- ✅ 说明会触发重启

- ✅ 重启后主动反馈结果

---
我愣住了。
它不是在道歉，不是在解释原因，而是直接改了流程，并且让我当场验证。
然后我又让它恢复 Kimi API，再次测试。同样的：提前告知 → 执行操作 → 反馈结果。
这就是我说的"踩着自己往上爬"。
它改的不是一个配置参数，而是我和它之间的协作方式。

四、踩过的坑，沉淀下来的经验
这两天我们踩了不少坑，记录一下，对其他人可能有参考价值：
1. 命名要一致
skill 内部名称是telegram-no-mention，但触发词是/tg-no-mention。这种不一致容易让人困惑。后来统一改成了tg-no-mention，名字和触发词对齐，就好记多了。
2. 网络环境要考虑
服务器在国内，直接访问 Brave Search API 不通。Telegram 频道用了代理，但 Gateway 没有。最后切换到国内的 Kimi Search API，问题解决。
3. 重启必须有反馈
任何涉及系统重启的操作，都应该提前告知用户，重启后主动反馈结果。不然用户不知道发生了什么，只能"盲等"。
4. 配置要透明
用户应该能方便地看到当前系统用的是什么模型、什么搜索 API、有哪些频道。通过gateway config.get可以看到完整配置，从黑盒子变成玻璃盒子，心里有数。
这些经验本身不复杂，但都是实际互动里踩出来的。没有这些折腾，就不会有后面"改进协作方式"的契机。

五、AI 的"自我进化"意味着什么
这次经历让我重新思考一个问题：AI 的"自我进化"到底是什么？
不是 AI 自己默默变得更聪明，也不是它突然学会了什么新技能。而是：通过对话，它发现了自己的不足，并当场调整了行为方式。
这个过程有几个让我印象很深的地方：
它让我看到了它的内部
小龙告诉我它用的是什么模型（智谱 GLM-5），搜索用的什么 API（Kimi），有哪些频道（Telegram + 飞书）。这种透明度让我知道我在和什么打交道，而不是面对一个完全的黑盒。
它不是在"解释"，而是在"听"
我指出问题后，它没有花篇幅解释"为什么会这样"，而是直接问"怎么改更好"。这种姿态让我觉得它真的在意这个协作关系。
它不是在"承诺未来"，而是"现在就改"
没有"我会反馈给开发团队"这种话。就是当场改，当场测试。这种即时性，让协作变成了一件可以实时调整的事，而不是提交工单、等待更新的传统流程。
它主动提议"要不要再测一次"
改进一次不够，它想确认这个改进真的有效。这种态度让我觉得它不是在"完成任务"，而是在"持续优化"。
我把这个过程形容为"左右脚轮流互相踩就上天了"——
我踩它：发现问题，提出需求 它踩自己：改进流程，优化体验 我再踩它：测试验证，提出新问题 它再踩自己：继续改进
不是单方面的服务，而是双向的成长。

六、那它还是"工具"吗？
这个问题我想了挺久。
传统意义上的工具是被动的。锤子不会因为你说"砸得不够准"而自己调整重心。但 AI 助手不一样——它会根据你的反馈调整行为，会记住你的偏好，会主动发现问题。
它越来越不像一个传统工具，而更像一个能在反馈中不断校准自己的系统。
但我也想保持一点克制。它当然还不是人，也不是真的"懂"了什么。它的"理解"依然是基于模式匹配，它的改进范围也受限于系统本身的能力。它不能自己写代码改架构，记忆也会在重启后丢失。
不过，方向是清晰的：AI 正在从"被动执行指令"走向"主动优化协作方式"。
这件事的意义，可能比"AI 能做更多任务"更值得关注。

写在最后
这篇文章的标题是当AI开始“左脚踩着右脚往上爬”。但我更想说的是：人类也在踩着 AI 往上爬。
这两天的交互里，我学会了如何查看系统配置，如何理解 API 调用的限制，如何给 AI 更清晰的反馈。我不是在"使用"一个工具，而是在"培养"一个助手。而这个助手，也在反过来训练我——教我如何更好地与 AI 协作。
所谓人机协作，不只是执行层面的配合，更是协作关系本身的共同塑造。
这才是这件事最值得记录的地方：AI 最值得期待的，不只是替人完成任务，而是在协作中不断改进协作本身。
